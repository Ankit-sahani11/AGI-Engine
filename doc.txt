Tip 1: Single Core Execution: Even if the SoC features a massive octa-core cluster, the hardware automatically selects a single primary core (the Boot CPU) to begin fetching instructions. All other secondary cores are natively placed into a low-power hardware standby or sleep state (Power-Down State), waiting for a software-driven wakeup command.Instruction State: The processor defaults to the 64-bit execution state (AArch64).Interrupt Masking: All physical asynchronous exceptions—including standard interrupts (IRQs), fast interrupts (FIQs), System Errors (SErrors), and Routing Aborts—are globally masked at the CPU core level. The processor will ignore external hardware signals until the bootloader explicitly unmasks them.
2. Managing Exception Levels (EL) and PrivilegeThe defining feature of the ARM64 architecture is its privilege hierarchy, divided into four distinct Exception Levels (EL). The Boot Privilege ParadoxWhen the Boot CPU wakes up, it starts execution at the highest implemented Exception Level, which is typically EL3 (Secure Monitor).
EL3 has complete, unrestricted access to both the Secure and Non-Secure physical memory spaces.A runtime Operating System (like Linux or macOS) is designed to execute at EL1 (Supervisor Mode), while virtualized environments run at EL2 (Hypervisor Mode).The bootloader's foundational theoretical duty is to configure the system properties while running in high privilege (EL3/EL2) and then perform a controlled architectural downgrade (Exception Return) to hand execution over to the operating system kernel at a lower privilege level (EL1) without compromising system stability.3. Register Configuration and Architectural SetupBefore the bootloader can drop the privilege level or load an operating system, it must manually program several critical system registers that define how the processor behaves.Enforcing Execution States (SCR_EL3 and HCR_EL2)The Secure Configuration Register (SCR_EL3) and Hypervisor Configuration Register (HCR_EL2) control the architectural state of the lower exception levels. The bootloader must explicitly write to these registers to establish:The Width of Lower Levels: It sets specific Register Width bits (RW bits) to ensure that when the processor drops to EL2 or EL1, it remains in 64-bit mode (AArch64) rather than accidentally dropping back into a legacy 32-bit (AArch32) mode.The Security World: It sets the Non-Secure (NS) bit to segment the system. This isolates secure silicon components (like hardware cryptographic accelerators or biometric data enclaves) from the generic, non-secure memory space where the main operating system will run.
Traps and System Access ControlBy default, early boot levels block advanced hardware functions. The bootloader must configure architectural control registers (such as CPTR_EL3 and CPTR_EL2) to disable floating-point and SIMD access traps. If left unconfigured, the instant the OS kernel attempts a vector math calculation or floating-point operation, the hardware will trigger a system-level fault, causing an immediate crash.4. The Architectural Mechanics of the Context Switch (EL Drop)The transition from a high exception level bootloader to a lower exception level operating system is achieved through a specialized hardware instruction loop known as an Exception Return (ERET).To the ARM64 hardware, dropping privilege is treated as if the processor is returning from an interrupt handler that occurred before the machine even turned on. The bootloader orchestrates this illusion using three architectural system registers:The Target Configuration Space (SPSR_ELx): The bootloader writes to the Saved Program Status Register. This maps out exactly what the processor state should look like the millisecond after the jump occurs. It tells the hardware what interrupts to unmask and defines the target level (e.g., configuring execution to resume in EL1h with the dedicated EL1 stack pointer).The Target Address Pointer (ELR_ELx): The bootloader loads the exact 64-bit base memory address of the operating system kernel or the next boot stage into the Exception Link Register.The Target Stack Segment (SP_EL1): The bootloader configures the stack pointer for the incoming level so that the operating system has immediate, clean memory workspace to allocate variables upon arrival.

Architectural Anatomy & Memory MappingA robust system isolates the bootloader from the main user application using a strict partition layout within the non-volatile Flash memory.Typical Memory MapSector 0 (Base Address, e.g., 0x0800 0000): Bootloader Vector Table & Execution Binary.Sector 1 (Configuration Space): Shared Flags (e.g., in EEPROM or specialized flash) to signal update modes or validate firmware status.Sector 2+ (Application Space, e.g., 0x0800 8000): Main User Firmware Image (with its own offset vector table).Multi-Stage BootingIn complex System-on-Chips (SoCs), bootloading occurs in sequential stages due to tight initial memory boundaries:ROM Bootloader (Stage 0): Hard-coded by the silicon manufacturer; sets up foundational clocks and reads hardware boot-pins.First-Stage Bootloader (FSBL / SPL): Initializes basic chip peripherals and configuration settings, then maps out external DRAM.Second-Stage Bootloader (SSBL): A full-featured environment (like Das U-Boot) that handles file systems, network connections, security verifications, and loads the OS kernel into memory.Critical Operational MechanicsHardware Initialization: The bootloader must program the Phase-Locked Loops (PLL) to configure system clock rates, shut down the watchdog timer initially to avoid unexpected loops, and prepare communication ports (UART, I2C, USB, or CAN).Integrity & Authentication (Secure Boot): Before running the primary application, the bootloader performs an integrity check (using CRC32 or SHA-256). In Secure Boot configurations, it uses asymmetric cryptographic keys (RSA or ECC) stored in One-Time Programmable (OTP) hardware fuses to verify the binary's digital signature.In-Application Programming (IAP): If a boot-pin or software flag demands an update, the bootloader enters upgrade mode. It streams new firmware data over a peripheral interface, erases the destination flash sectors, and writes the incoming binary into memory.Context Switching (The Jump): To pass complete control over to the main application, the bootloader performs three vital commands:Disables all active peripheral interrupts to prevent crash conditions.Updates the Main Stack Pointer (MSP) to the application's base stack address.Modifies the Program Counter (PC) to the address of the application's Reset Handler.

// ============================================================================
// File: bootloader.S
// Target: ARM64 (AArch64) Bare-Metal
// Purpose: Multi-Stage Initialization, Payload Copying, and EL Drop Jump
// ============================================================================

.section ".text.boot"
.global _start

// Memory Mapping Targets (Arbitrary reference layout for bare-metal SoC)
.equ BOOTLOADER_BASE,   0x40000000
.equ PAYLOAD_SOURCE,    0x40100000   // Location where payload sits in Flash/ROM
.equ PAYLOAD_DEST,      0x80000000   // Target RAM Execution Base Location
.equ PAYLOAD_SIZE,      0x00020000   // Size of code to move (e.g., 128 KB)
.equ BOOT_STACK_TOP,    0x4000F000   // Working stack allocation

_start:
    // ------------------------------------------------------------------------
    // Step 1: Core Identification & Core 0 Parking Check
    // ------------------------------------------------------------------------
    mrs     x0, mpidr_el1               // Read Multiprocessor Affinity Register
    and     x0, x0, #0xFF               // Mask out CPU ID core bits
    cbz     x0, .core0_continue         // If Core 0, continue to boot execution

.secondary_cores_loop:
    wfe                                 // Put non-boot cores into low-power sleep
    b       .secondary_cores_loop

.core0_continue:
    // ------------------------------------------------------------------------
    // Step 2: Establish Working Execution Stack Pointer
    // ------------------------------------------------------------------------
    ldr     x0, =BOOT_STACK_TOP
    mov     sp, x0

    // ------------------------------------------------------------------------
    // Step 3: Architecture State & Exception Level Configuration
    // ------------------------------------------------------------------------
    // Check our current Exception Level to safely manipulate registers
    mrs     x0, CurrentEL
    lsr     x0, x0, #2
    and     x0, x0, #3                  // Extract numeric level (0-3)

    cmp     x0, #3                      // Are we running inside EL3?
    b.eq    .from_el3                   
    cmp     x0, #2                      // Are we running inside EL2?
    b.eq    .from_el2
    b       .copy_payload               // Already in EL1, skip down-routing

.from_el3:
    // Configure EL3 Execution state (SCR_EL3)
    // Set RW bit (Bit 10) = 1 to enforce AArch64 execution state for EL2/EL1
    // Set NS bit (Bit 0)  = 1 to route to Non-Secure world
    mrs     x1, scr_el3
    orr     x1, x1, #(1 << 10)          // Next lower level is AArch64 [4]
    orr     x1, x1, #(1 << 0)           // Non-secure routing [5]
    msr     scr_el3, x1

    // Setup Saved Program Status Register (SPSR_EL3) to prepare a drop into EL2
    // Mask interrupts: F=1, I=1, A=1, D=1. Target execution state: EL2h (0b01009) [2]
    mov     x1, #0x3C9
    msr     spsr_el3, x1

    // Load the return entry handler address to point inside our EL2 layer
    adr     x1, .from_el2
    msr     elr_el3, x1
    eret                                // Exception Return to EL2 execution context

.from_el2:
    // Configure EL2 Execution state (HCR_EL2)
    // Set RW bit (Bit 31) = 1 to enforce AArch64 execution mode for EL1
    mov     x1, #(1 << 31)
    msr     hcr_el2, x1

    // Disable architectural traps for floating point/SIMD access routines
    mov     x1, #(3 << 20)              // Enforce no-trap state architectural controls
    msr     cptr_el2, x1

    // Disable architecture stage-2 translations initially
    msr     vttbr_el2, xzr

    // ------------------------------------------------------------------------
    // Step 4: Firmware/Payload Image Copy Sequence (In-Application Engine)
    // ------------------------------------------------------------------------
.copy_payload:
    ldr     x0, =PAYLOAD_SOURCE         // Reading index source register
    ldr     x1, =PAYLOAD_DEST           // Writing index destination register
    ldr     x2, =PAYLOAD_SIZE           // Total loop countdown limit tracking
    mov     x3, #0                      // Byte offset counter register

.copy_loop:
    // Read and Write memory blocks in hyper-efficient 16-byte pairs
    ldp     x4, x5, [x0, x3]            // Load pair from source
    stp     x4, x5, [x1, x3]            // Store pair to destination
    add     x3, x3, #16                 // Offset ahead by 16 bytes
    cmp     x3, x2                      // Complete verification limit?
    b.lt    .copy_loop                  // Continue loop if counter < payload size

    // ------------------------------------------------------------------------
    // Step 5: Cache Clean and Instruction Invalidation
    // ------------------------------------------------------------------------
    // Ensure modified binary instructions are explicitly written to RAM pipelines
    dsb     ish                         // Data Synchronization Barrier
    isb                                 // Instruction Synchronization Barrier

    // ------------------------------------------------------------------------
    // Step 6: Vector Tables & Stack Initialization for OS Execution Environment
    // ------------------------------------------------------------------------
    // Clean target state register spaces to avoid passing junk state registers
    msr     vbar_el1, xzr               // Zero out EL1 Vector Table until kernel maps it
    ldr     x0, =PAYLOAD_DEST           // Set target entry pointer
    
    // Allocate distinct execution stack boundary allocation for the OS Kernel execution
    mov     x1, #0x80F00000             
    msr     sp_el1, x1                  // Set target EL1 stack structure point

    // ------------------------------------------------------------------------
    // Step 7: Context Switch & Execution Transfer Jump (Drop to EL1)
    // ------------------------------------------------------------------------
    // Setup target configuration settings profile inside SPSR_EL2
    // Mask interrupts: F=1, I=1, A=1, D=1. Target execution mode: EL1h (0b00101) [2]
    mov     x2, #0x3C5
    msr     spsr_el2, x2

    // Set Exception Link Register to target the base address of the payload
    msr     elr_el2, x0

    // Wipe global purpose registers to prevent side-channel information leakage
    mov     x0, xzr
    mov     x1, xzr
    mov     x2, xzr
    mov     x3, xzr

    eret                                // Final Hardware jump. Drops to EL1 and executes
                                        // the code located at PAYLOAD_DEST.

// Adreno 610 Optimization: 

// mediump drastically reduces register pressure and ALU power consumption.

precision mediump float;


// Input from the Vertex Shader (must match location 0)

layout(location = 0) in vec2 inUV;


// Output to the Framebuffer

layout(location = 0) out vec4 outColor;


// --- Pakoda Color Palette ---

const vec3 C_PALE_GOLD = vec3(0.96, 0.82, 0.35); 

const vec3 C_GOLDEN_BROWN = vec3(0.80, 0.48, 0.12); 

const vec3 C_CRISPY_EDGE = vec3(0.45, 0.22, 0.05);


// --- Fast Procedural Noise ---

float hash(vec2 p) {

    p = fract(p * vec2(12.9898, 78.233));

    p += dot(p, p + 34.19);

    return fract(p.x * p.y);

}


float noise(vec2 p) {

    vec2 i = floor(p);

    vec2 f = fract(p);

    vec2 u = f * f * (3.0 - 2.0 * f);

    return mix(mix(hash(i + vec2(0.0, 0.0)), hash(i + vec2(1.0, 0.0)), u.x),

               mix(hash(i + vec2(0.0, 1.0)), hash(i + vec2(1.0, 1.0)), u.x), u.y);

}


float fbm(vec2 p) {

    float value = 0.0;

    float amplitude = 0.5;

    // Hardcoded 3 loops to avoid dynamic branching on mobile ALUs

    for (int i = 0; i < 3; ++i) {

        value += amplitude * noise(p);

        p *= 2.0;       

        amplitude *= 0.5; 

    }

    return value;

}


void main() {

    // 1. Scale UVs to simulate the size of the crispy flakes

    vec2 scaledUV = inUV * 15.0; 

    

    // 2. Generate layered organic batter shapes

    float structuralNoise = fbm(scaledUV);

    float crunchNoise = fbm(scaledUV * 2.5 + structuralNoise * 2.0);

    

    // 3. Color Mapping (Frying Simulation)

    float fryLevel = smoothstep(0.2, 0.7, crunchNoise);

    vec3 pakodaColor = mix(C_PALE_GOLD, C_GOLDEN_BROWN, fryLevel);

    

    // 4. Add the ultra-crispy edges

    float edgeLevel = smoothstep(0.65, 0.95, crunchNoise);

    pakodaColor = mix(pakodaColor, C_CRISPY_EDGE, edgeLevel * 0.6);

    

    // 5. Output final fragment

    outColor = vec4(pakodaColor, 1.0);

}
